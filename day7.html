先接上 Day 6：我们已经完成了什么？

为什么有了主题关键词，还需要继续优化？

Day 6 我们走完了 BERTopic 的基础流程：先用 SBERT 把摘要变成语义向量，再用 UMAP 降维、HDBSCAN 聚类，最后通过 CountVectorizer 和 c-TF-IDF 为每个簇提取代表词。

因此，我们已经有了一个初始主题表示。例如某个“文本摘要”主题，c-TF-IDF 可能给出 summarization、summaries、summary、abstractive 等关键词，并按权重排序。

但现在出现两个新问题：第一，词袋模型主要根据词频统计，不能充分理解两个词在语义上是否接近；第二，排名靠前的词可能彼此重复，例如 summary 和 summaries。这就引出了今天的内容：不推翻原来的主题，只在主题表示这一层增加新的优化模块。

今天的承上启下：Day 6 负责“生成初始主题关键词”；Day 7 负责“让关键词排序更符合语义、减少冗余”。下一步 Day 8 会继续学习用生成模型直接为主题生成简短标签。

一、先理解核心缺点：词袋模型不理解语义关系

词袋模型（Bag of Words）把文本看成词语及其出现次数的集合。CountVectorizer 统计词频，c-TF-IDF 再给词加权。它速度快、结果容易解释，但主要依据词项统计。

例如 summary 和 summaries 在字面上很相近；abstractive 和 evaluation 则可能代表不同方面。仅仅按照词频权重排序，不一定能得到最有信息量、最有区分度的一组词。

这里要区分两个概念：关键词权重是某个词在当前主题中的统计代表性；语义相似度是两个文本或向量在含义上的接近程度。它们不是同一种分数。

二、图5-19：重排序到底改变了什么？

看图左边：这是 Day 6 通过 c-TF-IDF 得到的原始关键词排序。右边：经过一个“重排器（表示模块）”之后，词的先后顺序发生变化。

重排序（Reranking）不是重新生成所有论文的向量，也不是重新聚类。它先拿到一组候选关键词，再用另一种标准重新评估这些候选词，调整它们的顺序。

图中 Summarization 和 Summaries 仍然靠前；Abstractive 被提前，而 Document、Extractive 等词的位置发生变化。重点不是“右边每个词都一定正确”，而是：初始 c-TF-IDF 排名可以被另一个模块进一步优化。

承上：c-TF-IDF 提供初始候选词和权重。
转折：初始排名不一定充分考虑语义。
因此：再接一个重排序模块，让它输出更新后的主题表示。

三、图5-20：“乐高积木块”是什么意思？

书中把新模块比作“乐高积木块”，意思是：BERTopic 的流程由多个可替换组件组成。前面的嵌入、降维、聚类、词袋和 c-TF-IDF 先建立主题；现在在主题表示的顶部，再插入一个重排序模块。

表示模块（Representation Model）是 BERTopic 中用来改善主题表示的组件。它接收已有的主题表示，进一步调整关键词或主题描述，而不是从头处理整套聚类流程。

图5-20中，下面五步仍是我们已经学过的流程：SBERT → UMAP → HDBSCAN → CountVectorizer → c-TF-IDF。第6步才是新增的“微调表示”。因此，今天不是抛弃 c-TF-IDF，而是在它上面继续优化。

为什么说它是模块化的？

模块化（Modularity）就是把一个复杂流程拆成职责相对独立的组件，使某一组件可以被替换或组合。原书强调，聚类阶段和主题表示阶段在很大程度上独立：例如可以保留 HDBSCAN 的分组结果，只替换主题关键词的优化方法。

四、为什么表示模块只需要按“主题数”运行？

假设有100万篇文档，最终聚成100个主题。如果我们要优化每篇文档，就可能要处理100万次；但如果目标是优化主题关键词，那么表示模块只需对100个主题分别处理。

这就是原书强调的效率优势：表示模块的应用次数通常与主题数量相关，而不是与原始文档数量相等。它仍然可能需要访问代表性文档或相关嵌入，但并不是为每篇文档重新执行一次完整的主题建模。

注意：“每个主题一次”是对模块应用粒度的解释，不等于内部永远只做一次向量计算；例如 MMR 在一个主题内部还会迭代选择关键词。

五、先做比较：为什么要保存原始主题表示？

如果我们直接更新 topic_model，原来的关键词可能被新结果覆盖。为了知道“优化前后到底变了什么”，书中先使用 deepcopy 保存一份独立副本。

from copy import deepcopy

# 保存原始主题表示
original_topics = deepcopy(topic_model.topic_representations_)
  • topic_model.topic_representations_：当前模型保存的主题表示，通常包含每个主题的词及其权重。
  • deepcopy(...)：深拷贝，创建一份独立副本，避免后续更新模型时原始比较数据也跟着变化。
  • original_topics：专门用于保存优化前的结果，后面用它和更新后的主题表示比较。

这里的重点不是深拷贝算法本身，而是实验比较的基本原则：先保存基线（baseline），再修改模型，最后比较差异。

比较函数在做什么？

def topic_differences(model, original_topics, nr_topics=5):
    df = pd.DataFrame(columns=["Topic", "Original", "Updated"])

    for topic in range(nr_topics):
        og_words = " | ".join(
            list(zip(*original_topics[topic]))[0][:5]
        )
        new_words = " | ".join(
            list(zip(*model.get_topic(topic)))[0][:5]
        )

        df.loc[len(df)] = [topic, og_words, new_words]

    return df

逐步看：range(nr_topics) 遍历前几个主题；original_topics[topic] 取出某个主题的原始词项与权重；model.get_topic(topic) 取出当前更新后的主题表示；zip(*...) 将词和权重这类成对数据拆成两列；[0][:5] 只取前5个词；最后把原始词和更新词放进表格。

这个函数只是为了比较、展示结果，它本身不训练模型，也不执行关键词优化。

六、第一种“乐高积木块”：KeyBERTInspired

新术语：KeyBERT。这是一个受 BERT 嵌入启发的关键词提取方法。其基本思路是：把候选关键词和文档都转成嵌入向量，再比较它们的余弦相似度，选择与文档语义更接近的关键词。

KeyBERTInspired是 BERTopic 提供的一个表示模块，借鉴了这种“词与文档比较语义”的思路。它不是直接把整个主题交给一个生成模型重写，而是利用代表性文档和候选关键词的嵌入关系，对已有关键词重新排序。

按图5-22逐步看它怎么工作

  1. 找代表性文档：对某个主题，先从该主题的文档中挑选最有代表性的几篇。原书说明会参考文档的 c-TF-IDF 表示与对应主题之间的相似程度。
  2. 把代表性文档变成向量：使用嵌入模型对这些文档进行编码。
  3. 计算平均文档嵌入：将代表性文档的嵌入进行平均，得到这个主题的一个语义中心表示。
  4. 把候选关键词也变成向量：例如 cat、that、cute。
  5. 计算余弦相似度并重新排序：比较候选词向量与主题平均文档向量的接近程度，重新排列关键词。
这里有两个不同的“向量”：Day 3 的文档嵌入帮助我们表示整篇摘要；这里还会把候选关键词也编码成向量。然后比较“词向量”和“代表性文档的平均向量”，不是把 c-TF-IDF 权重直接当作嵌入向量。

代码：把 KeyBERTInspired 接入 BERTopic

from bertopic.representation import KeyBERTInspired

representation_model = KeyBERTInspired()

topic_model.update_topics(
    abstracts,
    representation_model=representation_model
)

topic_differences(topic_model, original_topics)

representation_model 是新建的表示模块对象；update_topics 使用它更新现有主题的表示；abstracts 是原始文档列表；最后调用比较函数观察更新前后的关键词。

非常重要：这里不是再次执行 fit，也不是重新运行 UMAP 和 HDBSCAN。已有主题分组仍然作为基础，变化的是主题的表示方式。

KeyBERTInspired 的优势和局限

原书指出，更新后的主题表示通常更容易阅读，尤其能减少一些停用词。但嵌入模型也可能无法很好表示某些专业实体或缩写。例如书中提到 nmt（神经机器翻译）可能被删掉；对领域专家而言，这个缩写很有价值。

这告诉我们：语义相似度高，不代表关键词对领域专家一定最有用。因此，KeyBERTInspired 能改善表示，但不是永远正确的自动答案。

七、第二种“乐高积木块”：最大边际相关性（MMR）

KeyBERTInspired 之后，关键词可能仍然重复。例如 summaries 与 summary 很相似。即使它们都与主题相关，同时保留在前几名，也可能浪费主题表示有限的位置。

新术语：最大边际相关性（Maximal Marginal Relevance，MMR）。它的目标不是单纯找最相似的词，而是选择一组既与主题相关、彼此又尽量不重复的关键词。

用一个直观例子理解

假设主题是“文本摘要”，候选词是：

候选词与主题相关与已选词重复程度
summarization高—（第一个词）
summary高很高
summaries高很高
evaluation较高较低
ROUGE较高较低

如果只按相关性排序，summary 和 summaries 可能连续占据多个位置；MMR 会考虑已经选了什么，尽量再挑一个能带来新信息的词。

MMR 的工作逻辑

  1. 先得到一组候选关键词（原书举例约30个）。
  2. 将候选关键词转换成嵌入向量。
  3. 先选一个与主题相关的词。
  4. 每次迭代时，综合考虑候选词与主题/文档的相关性，以及它与已选关键词之间的相似程度。
  5. 选择一个既相关、又能增加多样性的词，直到得到较小的关键词集合（原书举例约10个）。

新术语：多样性参数（diversity）。它控制MMR更偏向关键词多样性还是主题相关性。参数调大，通常会更强调候选词之间的差异；参数调小，通常会更偏向相关性。它不是主题数量，也不是相似度阈值。

代码：使用 MMR 更新主题表示

from bertopic.representation import MaximalMarginalRelevance

representation_model = MaximalMarginalRelevance(
    diversity=0.2
)

topic_model.update_topics(
    abstracts,
    representation_model=representation_model
)

topic_differences(topic_model, original_topics)

diversity=0.2 是本书示例中的参数值。它告诉 MMR 在选择关键词时考虑多样性；不是“20%的关键词要被删除”。

原书展示的结果中，主题0从 speech | asr | recognition | end | acoustic 变成 speech | asr | error | model | training。主题4也不再只是围绕 summary 的近义词，而加入了其他相关词。重点是结果更有多样性，不代表每个更新词都必然比原词更准确。

八、KeyBERTInspired 和 MMR 到底有什么区别？

比较维度KeyBERTInspiredMMR
核心问题候选关键词是否符合主题语义？关键词是否过度重复？
主要依据代表性文档平均嵌入与候选词嵌入的余弦相似度主题相关性与候选词之间的多样性
主要作用按语义相关性重新排序减少冗余，挑选互补关键词
可能的局限可能丢掉领域缩写或特殊术语过度追求多样性时，可能保留较弱的主题词

二者不是非此即彼的聚类算法，也不会决定主题数量。它们是作用在主题表示阶段的可选组件。原书图5-21说明 BERTopic 可以选择一个表示模块，也可以堆叠多个模块。

Day 7 的核心不是“又出现两个新算法”，而是理解 BERTopic 的模块化设计：先用 c-TF-IDF 快速得到初始关键词，再根据需要选择语义重排或多样性优化模块。

几个概念不要混淆：
1. c-TF-IDF：统计并加权主题中的候选词。
2. KeyBERTInspired：依据词与代表性文档的语义接近程度重排关键词。
3. MMR：在相关性基础上减少关键词之间的重复。
4. Representation Model：BERTopic 中用于微调主题表示的模块总称。
5. update_topics：更新主题表示，不等于重新做一遍降维和聚类。

十、自测：确认你能把逻辑讲出来

1. Day 6 已经有 c-TF-IDF 关键词，为什么还要 KeyBERTInspired？

c-TF-IDF 根据词频与类间分布产生初始排序，但词袋统计不充分考虑语义。KeyBERTInspired 借助嵌入向量比较候选关键词与代表性文档的语义接近程度，进一步重排。

2. KeyBERTInspired 会重新运行 HDBSCAN 吗？

不会。它在已有主题基础上更新主题表示，不需要重新执行降维和聚类。

3. 为什么 MMR 不只选与主题最相关的词？

因为最相关的词可能彼此高度相似，例如 summary 和 summaries。MMR 同时考虑相关性和多样性，避免关键词列表被近义词占满。

4. diversity=0.2 是什么意思？

它是控制关键词多样性取向的参数，不是20%的关键词比例，也不是簇数。具体效果应结合模型与数据观察。

5. 为什么要 deepcopy 原始主题表示？

为了保留优化前的独立副本，避免更新主题表示后失去比较基线。

6. BERTopic 模块化意味着什么？

嵌入、降维、聚类和主题表示由不同组件承担；可以替换某个组件或叠加表示模块，而不必把整个流程推倒重来。
