ArXiv 数据集与文档嵌入

《图解大模型：生成式 AI 原理与实战》｜第5章 5.1、5.2.1

原书第115–116页｜预计 30–40 分钟

01｜今天要解决的问题

第5章要把大量学术摘要自动分组。今天先完成两件事：读懂实验数据从哪里来；理解如何把每篇摘要转换成一个数值向量。

先记住整体思路：一篇文章是一份文档；嵌入模型把文档变成向量；后续算法再根据向量之间的关系寻找文档簇。

02｜5.1 ArXiv 文章：计算与语言

原书使用 ArXiv 上计算与语言（cs.CL）领域的文章做实验。ArXiv 是面向计算机科学、数学和物理等领域的开放学术文章平台。书中所用的 arxiv_nlp 数据集包含 1991—2024 年 ArXiv cs.CL 板块的 44,949 篇摘要。

为什么选择摘要？本章需要比较文章讨论的内容。摘要是文章内容的文本表达，可以作为后续语义嵌入的输入。标题等元数据则可以帮助识别、查看对应文章。

原书代码：加载数据集

# 从 Hugging Face 加载数据
from datasets import load_dataset
dataset = load_dataset("maartengr/arxiv_nlp")["train"]

# 提取元数据
abstracts = dataset["Abstracts"]
titles = dataset["Titles"]
代码含义
load_dataset(...)从 Hugging Face datasets 加载指定数据集
["train"]取出该数据集提供的 train 数据分区
dataset["Abstracts"]取出所有文章摘要，形成摘要列表
dataset["Titles"]取出所有文章标题

这里的 abstracts 是后续嵌入模型的主要输入。书中说明还会为每篇文章的年份创建变量，但本页展示的代码片段明确列出的只有摘要和标题提取。

03｜5.2 文本聚类的通用流程

原书将当前常见的通用文本聚类流程归纳为三步，每一步对应一种算法：

① 嵌入模型
输入文档 → 嵌入向量
→
② 降维模型
高维向量 → 低维向量
→
③ 聚类模型
向量 → 文档簇

注意这三个模型不是在做同一件事：第一个负责表示文本含义，第二个改变向量所在空间的维度，第三个根据向量分布来分组。

04｜5.2.1 嵌入文档：把文字变成向量

嵌入向量（embedding）是试图捕捉文本含义的数值表示。对聚类而言，我们希望语义相似的文档在向量空间中也具有相近的表示，因此原书强调应选择针对语义相似度任务优化的嵌入模型。

为什么选 gte-small？

原书参考 MTEB 排行榜，选择 thenlper/gte-small：作者认为它在聚类任务上表现不错，而且模型体积较小、推理速度更快。书中将它与上一章使用的 sentence-transformers/all-mpnet-base-v2 作比较。

原书代码：生成摘要嵌入

from sentence_transformers import SentenceTransformer

# 为每个摘要创建嵌入向量
embedding_model = SentenceTransformer("thenlper/gte-small")
embeddings = embedding_model.encode(
    abstracts, show_progress_bar=True
)

逐行理解：

  1. SentenceTransformer(...)：加载指定的句子/文本嵌入模型。
  2. embedding_model：保存加载后的模型对象。
  3. encode(abstracts)：把摘要列表中的文档编码成向量。
  4. show_progress_bar=True：显示处理进度，不改变向量含义。

05｜关键结果：为什么是 (44949, 384)？

embeddings.shape
(44949, 384)

这表示嵌入结果是一个二维矩阵：

维度含义
44,949 行对应 44,949 篇文章摘要，每行一个文档向量
384 列每个文档向量包含 384 个数值

可以把它想成一张表：每一行是一篇文章，每一列是这个向量的一个特征维度。注意，384 个数值不是 384 个词，也不是 384 篇文章；它们共同构成这一篇文档的语义表示。

关键连接：你之前学过句子嵌入和余弦相似度。这里把每篇文章摘要编码成向量后，就能用向量间的距离或相似度来比较文档，为下一步降维和聚类准备输入。

06｜自测

1. 为什么使用摘要而不是直接对文章编号聚类？

文章编号只用于标识，不表达文章讨论的语义内容。摘要包含文本内容，嵌入模型才能据此形成语义表示。

2. 44,949 × 384 分别代表什么？

44,949 篇摘要，每篇摘要对应一个 384 维向量。

3. 为什么要选择语义相似度表现较好的嵌入模型？

聚类的目标是发现语义相似的文档组，嵌入向量应尽量保留文本语义关系。

4. embedding model 和 cluster model 是一回事吗？

不是。嵌入模型负责把文档变成向量；聚类模型负责根据向量之间的关系形成簇。

加深讲解 · 原书第115—116页

一、从原始论文到语义矩阵

书中的数据集包含44,949篇 ArXiv cs.CL 文章摘要。abstracts 是摘要列表；titles 是对应的标题列表。前者用于编码语义，后者方便在后面查看、展示聚类结果。

为什么是矩阵而不是一个向量？

一个摘要对应一个384维向量，也就是一行384个数；44,949个摘要对应44,949行。embeddings.shape 才会输出 (44949,384)。这里第一维是文档数量，第二维是每个文档的表示维度，不能反过来理解。

二、嵌入表示和词袋表示有什么差别？

词袋：使用词频表示文本，强调哪些词出现了、出现几次；语义嵌入：借助预训练模型把文本转换成更紧凑的数值表示，争取保留句子或文档的语义关系。因此，不同的词语也可能得到相似的语义向量。例如“机器翻译系统”和“自动跨语言转换”字面不同，但研究意义可能相近。

注意：这不是说任意嵌入模型都能完美理解语义，也不是说384个数字各自对应一个确定的中文词。向量各维往往共同作用，语义信息是分布式表示。

三、逐行解释原书代码

from datasets import load_dataset
dataset = load_dataset("maartengr/arxiv_nlp")["train"]
abstracts = dataset["Abstracts"]
titles = dataset["Titles"]

from sentence_transformers import SentenceTransformer
embedding_model = SentenceTransformer("thenlper/gte-small")
embeddings = embedding_model.encode(abstracts, show_progress_bar=True)

print(embeddings.shape)
# (44949, 384)
代码重点理解
load_dataset(...)加载数据集，不是训练NLP模型
["train"]选择数据分区，不表示这一节要进行有监督训练
SentenceTransformer(...)加载预训练的嵌入模型
encode(abstracts)对摘要列表编码，得到整个文档嵌入矩阵
show_progress_bar=True显示处理进度，和语义维度无关

四、聚类为何要先有向量？

传统距离和聚类算法处理的是可计算的数值对象。文本本身不方便直接使用这些算法，因此先转为数值向量。如果语义关系保留得较好，讨论相近主题的论文在向量空间里就更有希望靠近；下一步才考虑将这些高维向量降到较低维度。

自测：为什么 384 不表示每篇摘要恰好有384个词？

384是 gte-small 生成的固定向量维数，与原文词数不同；长短不同的摘要都可以获得同维度表示。
